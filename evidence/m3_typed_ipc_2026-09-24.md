## What the result demonstrates

Two isolated EL0 principals with separate TTBR0 roots and separate kernel-owned
capability tables:

1. message=delivered: principal A (channel WRITE capability) sent a fixed-size
   typed Message (kind, three payload words, MemoryRegion, ObjectId) into the
   kernel-owned bounded ring; principal B (channel READ capability) received a
   message whose every field matched what A sent.
2. cap=delegated: A delegated its object capability into B's table through
   CapTable::derive_into, which requires DERIVE on the source, rejects rights
   escalation, and links the child to its parent for tree revocation.
3. rights=attenuated: the child carries READ only. B's object WRITE through the
   derived handle was denied (MissingRights) and recorded as attenuation.
4. forged=denied: B presented a handle with a corrupted generation; the
   capability table rejected it as invalid.
5. revoked=denied: the kernel revoked A's ancestor capability
   (CapTable::revoke across both tables); B's derived handle then failed to
   resolve at all.

Send and receive rights are enforced independently (A's send handle cannot
receive; B's receive handle cannot send), and delegation targets only the
active principal's counterparts, so no task can delegate authority it does not
hold.

## Host tests (10, in ipc.rs)

message ABI fixed size/alignment; channel FIFO, bounded and wrap-on-drain;
send requires WRITE and receive requires READ; stale/forged handles invalid;
delegation without DERIVE denied; rights escalation rejected; receiver table
full rolls back cleanly (source stays usable); attenuated child cannot write
or re-delegate; ancestor revocation reaches the derived child; end-to-end
send -> delegate -> receive -> read with write denied.

## Design notes

- `CapTable::derive_into` is the delegation primitive. `CapTable::transfer`
  (same-rights copy, no ancestry) is not used by the proof and remains
  available; attenuation with revocation ancestry is the M3 security model.
- Channels are kernel-owned fixed rings (8 x 56-byte repr(C) messages); there
  is no global channel lookup that bypasses the caller's capability table.
- The two principals run sequentially with separate TTBR0 roots; concurrent
  multi-task scheduling is #29's domain and is deliberately not mixed in.
