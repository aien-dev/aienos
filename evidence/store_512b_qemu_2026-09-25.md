## What each tier proves, and what it does not

| Tier | Marker | Method | Claim | Not claimed |
|---|---|---|---|---|
| Smoke | `STORE_NVME_INTEGRATION_512B_QEMU` | provision, one transaction, reopen through the real NVMe driver at 512-byte LBA | the Store engine runs over 512-byte geometry via `BoundedNvme` | Machine 1 behaviour |
| 1 | `STORE_512B_CRASH_OBSERVED_QEMU` | host `SIGKILL`s QEMU at each of the 7 engine checkpoints, settle 0 and 3, then reopens | after a VM/process crash at any checkpoint the store reopens `Valid` at generation N or N+1 as ADR 0015 orders | power loss: QEMU's accepted writes survive in the host file whether flushed or not; volatile-cache loss is #133's scope |
| 2a | `STORE_512B_ROOT_TEAR_CLOSURE` | host proof over the Tier 1 images killed at `after_first_flush` and `after_final_flush`: the images differ only in one superblock slot, and all 256 sector subsets of that 8-sector write are enumerated | on a 1-LBA-atomic device (AWUPF=0) a torn root write can only leave the old or the new slot, because every non-zero superblock byte lies in sector 0 and the engine only overwrites a zero or valid slot (sectors 1..7 zero in both) | device behaviour below one-LBA atomicity |
| 2b | `STORE_512B_INJECTED_ROOT_RECOVERY_QEMU` | deterministic media-corruption injection into the inactive slot by `aienos-store-tool` (kernel encoder and CRC; CRC recomputed so each case reaches the check it names) | the engine's malformed-peer, graph-bad-newer and unsupported-version decisions hold over the native NVMe path | these are not crashes and not torn writes |

The peer classification in every line is `Store::peer_condition()`, the
engine's own decision at open, not a re-derivation in the guest.

## Changes from the first #136 revision

- Tier 2 renamed from "deterministic torn root recovery" to injected-root
  recovery. The old cases pre-filled the slot with `0xAA`, a state the engine
  never writes, and applied the magic and reserved defects after the CRC, so
  all three only exercised the CRC check.
- Injection base moved from genesis (`before_first_write`) to
  `after_first_flush`, with the real generation-2 superblock as the source.
- `os.urandom` garbage replaced by a fixed-seed xorshift64 stream.
- All `python3` removed from the script (`aienos-store-tool`).
- Guest peer telemetry now comes from the engine (`PeerCondition`); the old
  guest heuristic labelled any decodable peer `GraphBad` from mount state.
